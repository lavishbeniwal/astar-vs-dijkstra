Dijkstra searches in every direction at once, street by street, until it happens to reach your destination. A* asks one more question at every corner: how far is it still, as the crow flies? That one guess lets it skip nearly three of every four intersections. And the route it finds is never a meter longer.

Two ways to find the way.

Both algorithms grow outward from the start, one intersection at a time. The only difference is which intersection they pick next.

Dijkstra

Uniform-cost search

Always picks the closest unexplored intersection to the start. The search ripples out evenly, like a stone dropped in water, with no idea where the destination is.

f(n) = g(n)0 intersections explored

A*

Informed search

Picks the intersection with the lowest distance driven so far plus a straight-line guess of the distance still to go. So the search leans toward the destination.

f(n) = g(n) + h(n)0 intersections explored

g(n)

Meters actually driven from the start to intersection n, along real road segments.

h(n)

Great-circle distance from n to the destination, computed with the haversine formula.

Why it stays optimal

No road trip is shorter than the straight line, so h(n) never overestimates. That makes the guess admissible, and A* is guaranteed to return the shortest route.

Tech specs.

Algorithms

  • Dijkstra's algorithm (uniform-cost search)
  • A* search, ordered by f(n) = g(n) + h(n)
  • Both use a binary heap with an insertion counter to break ties

Heuristic

  • Haversine great-circle distance, Earth radius 6,371 km
  • Admissible: never overestimates a real road trip, so A* stays optimal

Map data

  • OpenStreetMap drivable road network for Manhattan, via OSMnx
  • 4,634 intersections and 9,916 directed road segments
  • Edge weights are real lengths in meters. One-way streets are never forced two-way.
  • Cached locally as GraphML after the first download

Interface

  • Streamlit web app
  • Pick places from a list, or click them on a Folium map
  • Node-by-node animated replay, side-by-side metrics and a static comparison map for reports

Verification

  • Unit tests: equal optimal cost, connected paths whose cost matches their edges, A* never exploring more than Dijkstra, unreachable goals, and start equal to goal
  • 147-trip batch experiment, exported to CSV and scatter plots

Built in five phases

  • Both algorithms, validated on a synthetic 15 × 15 grid
  • Moved onto Manhattan's real road network
  • Side-by-side maps of every explored intersection
  • Interactive demo with animated search replay
  • Batch experiment across 147 random trips

Built with

  • Python · OSMnx · NetworkX · NumPy · pandas · Matplotlib · Folium · Streamlit

Run it yourself.

Install, launch, and race on your own machine. The first run downloads Manhattan in about a minute. After that it loads instantly.

# Install the dependencies
pip install -r requirements.txt

# Launch the interactive race
streamlit run app.py

# Reproduce the 147-trip study
python -m experiments.batch_comparison

# Run the tests
python -m unittest discover -s tests
  1. Results from experiments/batch_comparison.py: 150 random start and end pairs at least 300 m apart (seed 42), of which 147 were reachable by car. Averages are means across those 147 trips. Search times come from the Python implementation and vary by machine.
  2. The race on this page runs a JavaScript port of the project's Dijkstra and A* on the same road network, exported from data/manhattan_drive.graphml. It explores the same number of intersections as the Python version. Places are snapped to the nearest intersection.
